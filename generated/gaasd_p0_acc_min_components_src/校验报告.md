# CARLA ACC 最小组件 C++ atomic 边界组件校验报告

## 校验依据

- 规范文件：`docs/C++代码规范.docx`
- 规范版本：`v1.0.33`
- 校验日期：2026-06-16
- 校验范围：本目录下 `include/`、`src/` 和 `CMakeLists.txt`

## 结论

本目录中的六个组件已改为 GAASD `FuncModule<Traits>` 结构化组件，并通过
GCC 9.4 C++20 自包含编译。根据 GAASD 团队确认，`@type atomic` 组件的
`run()` 内部允许按具体业务自由实现，因此 CARLA 输入/输出边界组件可以在
`run()` 中调用 `carla_adapter_*` C ABI。

当前实现采用“边界原子组件”路线：

- `CARLAACCEgoSpeed`、`CARLAACCLeadSpeed`、`CARLAACCLeadDistance`、
  `CARLAACCDriverCommand` 在 `run()` 中调用 adapter 读取 CARLA/Bridge
  数据。
- `CARLAACCLongitudinalCmd` 在 `run()` 中调用 adapter 发布纵向控制命令。
- `CARLAACCComputeTargetSpeed` 仍为纯计算组件，不访问 adapter。

## 规则检查

| 规则类别 | 检查结果 |
|---|---|
| ENG-001～ENG-006 | 目录由 `include/`、`src/`、`CMakeLists.txt` 组成；模块继承 `FuncModule<Traits>` |
| INC-001 | 每个 `.cpp` 只包含自身对应的 `.hpp` |
| TYPE-001～TYPE-015 | 每个 Traits 均定义 `Input/Output/Param/State/Sub`；组件端口不含指针和第三方类型 |
| CTOR-003 | 无子模块组件统一使用 `using FuncModule::FuncModule` |
| RUN-001～RUN-011 | 每个 `.cpp` 仅定义一个固定签名的 `run(const Input&, Output&)` |
| BODY-006 | 组件端口不用裸指针；边界组件内部调用 adapter 的 C ABI 指针出参由 atomic 业务实现规则覆盖 |
| BODY-023～BODY-029 | 边界组件允许调用 `carla_adapter_*`；ZMQ/JSON 仍隔离在 adapter 动态库中 |
| BODY-030～BODY-047 | 业务逻辑使用基础运算、命名条件变量、`if/else` 和 `std::clamp` |
| BODY-057～BODY-068 | 所有结果均显式写入 `output`，无隐藏全局状态 |
| CMT-034～CMT-036 | 函数体语义块和输出赋值均使用 `/** @brief ... */` 注释 |
| DEP-004～DEP-008 | 组件源码只声明并调用 adapter C ABI；ZMQ/JSON 第三方依赖不进入组件源码 |

## 边界说明

`tools/carla_bridge/adapter/src/carla_gaasd_adapter.cpp` 是 ZMQ/JSON 运行时适配库，
不是 GAASD 扫描组件，不应与本目录组件放在同一次组件扫描中。生成工程运行时
必须链接 `libcarla_gaasd_adapter.so`，否则边界组件能扫描和编译为静态库，但最终
仿真链接或运行时无法解析 `carla_adapter_*` 符号。

采用该路线时的职责划分为：

```text
GAASD atomic 边界组件 run()
  -> carla_adapter_read_* / carla_adapter_publish_*
  -> libcarla_gaasd_adapter.so
  -> ZMQ/JSON
  -> carla_bridge.py
  -> CARLA
```
