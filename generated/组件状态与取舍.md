# CARLA 组件改写状态与取舍

> 记录日期：2026-06-03
> 背景：新版 GAASD 2.7.0.5 要求组件为 C++20 `FuncModule<Traits>` 格式（见 `docs/C++代码规范.md`）。
> 本目录 `generated/` 下为旧版各组件源码按新规范改写后的结果，已在 docker `ubuntu:env` 自包含编译通过。

## 取舍结论（2026-06-03 决定）

维护范围：**核心两组（acc_min I/O + lks）+ 保留 p1 未来扩展**。其余标为废弃/被取代，不再投入扫描入库与维护。

## 分级清单

### 🟢 核心在用 — 必须维护、优先扫描入库

| 工程 | 组件 | 在用方 |
| --- | --- | --- |
| gaasd_p0_acc_min_components_src | CARLAACCEgoSpeed、CARLAACCLeadSpeed、CARLAACCLeadDistance、CARLAACCLongitudinalCmd | newaccpro2（ACC 基础版）|
| gaasd_p0_acc_min_components_strict_src | CARLAACCEgoSpeed、CARLAACCLeadSpeed、CARLAACCLeadDistance、CARLAACCLongitudinalCmd | 新版 GAASD 严格扫描 / 入库讨论版 |
| gaasd_lks_components_src | CARLALKSLateralOffset、CARLALKSHeadingError、CARLALKSValid、CARLALKSControlCmd | lkspro1（LKS 基础版）|

### 🟡 未来扩展 — 保留待用

| 工程 | 组件 | 用途 |
| --- | --- | --- |
| gaasd_p1_components_src | CARLAObjectList、CARLALateralCmd、CARLAControlCmd | 障碍物列表 / 横向 / 横纵联合控制，高级场景才需要 |

### 🔴 废弃 / 已被取代 — 不再维护

| 组件 | 原因 |
| --- | --- |
| gaasd_acc_decision_components_src（ACCDecision、ACCTimeHeadway）| 决策层改用「真值表 + 基础运算块」在画布上实现（零 C 代码方案），这套 C 决策组件是被放弃的并行尝试 |
| gaasd_p0_components_src（CARLAEgoState、CARLALeadVehicle、CARLALongitudinalCmd、CARLAChassisFeedback）| 多输出版，因 GAASD 多输出端口未连线传参缺陷，已被 acc_min 单输出版取代 |
| CARLAACCComputeTargetSpeed（在 acc_min 工程内）| 目标速度公式改用基础运算块在画布上计算，此 C 组件未被使用 |

## 备注

- 已改写但被列为废弃的组件，代码仍保留在 `generated/` 下（编译通过），仅不投入后续扫描/入库/维护；若日后方案变更可随时启用。
- `gaasd_p0_acc_min_components_src` 是当前可运行联调版，组件 `run()` 内仍通过 adapter 访问 Bridge；`gaasd_p0_acc_min_components_strict_src` 是严格扫描版，已移除 `extern "C"`、`carla_adapter_*` 和指针出参，真实 CARLA 通信需由 GAASD 运行时/节点层提供输入绑定和输出发布。
- 所有保留组件的最终验证（被新版 codescan 正确扫描入库）依赖团队提供与新版 GUI 配套的新版 codescan；当前本地 codescan 为旧版 C 扫描器，无法识别 C++ FuncModule 格式（见 WORKLOG 2026-06-03）。
