## 当前问题

### 1. `GlobalParams` 被重复定义，阻断工程编译

代码生成器同时从自定义全局类型和全局参数配置生成了 `GlobalParams`：

- `GlobalContextTypes.hpp` 第 24 行定义了一次 `control::GlobalParams`。
- `GlobalContext.hpp` 第 11 行又定义了一次同名结构体。
- `GlobalContext.cpp` 随后实现 `GlobalParams::reset()`，但编译器首先匹配到的重复类型没有该函数声明，因此产生连带错误。

最新编译日志中的直接错误为：

```text
redefinition of 'struct control::GlobalParams'
no declaration matches 'void control::GlobalParams::reset()'
```

相关文件：

- `project/lks2/icvos/blocks/functions/dictionaryData/GlobalContextTypes.json`
- `project/lks2/icvos/blocks/functions/dictionaryData/GlobalVariable.json`
- `project/lks2/icvos/blocks/functions/dictionaryData/GlobalContext.json`
- `project/lks2/icvos/src/temp_codegen_output/GlobalContextTypes.hpp`
- `project/lks2/icvos/src/temp_codegen_output/GlobalContext.hpp`
- `project/lks2/log/2026-08-11.log`

该问题必须从画布/字典源配置中移除重复的 `GlobalParams` 类型。只删除一次生成目录中的头文件不能解决问题，下次生成仍会复现。

#### 全局参数的实际存储边界

工程目录中的上述三个 JSON 是代码生成时复制到 `icvos/blocks` 的快照，不是 GAASD 界面加载全局参数的主数据源。当前本机实际使用的主数据位于：

```text
/home/aiden/gaasd_versions/gaasd-2.7.0.5/home/gaasd_server/
  components/THICV/dictionaryData/
```

其中需要同时保存和迁移：

```text
GlobalVariable.json
GlobalContext.json
GlobalContextTypes.json
```

只把 `lks2` 工程发送到另一台电脑，导入过程不会把工程快照反向注册到对方的 `gaasd_server`，因此对方的全局参数页面可能为空。复现本问题时，必须在关闭 GAASD 后备份并安装这三份后端字典文件，再重新启动 GAASD、打开工程并生成代码。尤其需要保留当前 `GlobalContextTypes.json` 中重复存在的 `GlobalParams`，否则只能恢复参数，不能复现结构体重复定义问题。

### 2. 通道映射没有生成到 `c_process` 和 FuncStep

`temp_callback_info.json` 已识别出完整的 LKS 映射关系，包括：

- `lks_input` 到 `executeLks`：自车速度、制动状态、驾驶员转向、道路曲率、`c0`～`c3` 和 `frame_id`。
- `executeLks` 到 `lks_output`：`steerRad`、`isControlEnabled` 和 `frame_id`。

但最终生成代码没有实现这些赋值：

- `c_process` 的 `Input` 和 `Output` 结构体为空。
- `c_process::run()` 只创建未赋值的 `executeLks_in`，调用算法后也没有读取 `executeLks_out`。
- FuncStep 只使用静态空输入、空输出调用 `process.run()`。

因此当前 FuncStep/示波器路径无法向 LKS 算法提供真实输入，计算结果也无法写回输出通道。

### 3. Pangu 主业务节点仍为空实现

生成的 Pangu 主节点没有形成可运行的业务链路：

- `LoadConfig()` 也没有解析运行参数。

这意味着即使先手工绕过 `GlobalParams` 编译错误，Pangu 节点仍不会周期执行 LKS 算法。

### 4. 新生成的 ZMQ 输入输出节点仍是 ACC 专用骨架

新版工具生成了分离的 `AccZmqInputModule` 和 `AccZmqOutputModule`，但当前实现不能用于 LKS：

- 输入节点仍使用 `AccZmqInputBridge`，只处理 ACC 的自车速度、前车速度、前车距离和驾驶指令。
- 输入节点轮询得到状态后没有发布给 Pangu LKS 业务节点。
- 输出节点的 `Proc()` 为空，没有读取 LKS 输出并发送至 CARLA Bridge。
- 底层 `acc_zmq_bridge.cpp` 发布控制时仍固定 `steer_rad=0`。
