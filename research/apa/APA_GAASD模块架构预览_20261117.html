安全按检查位置分布，底层算法共用

任务准入、搜索扩展、候选检查、接收复核、在线控制各自调用相应安全能力。共用坐标、包络、碰撞、扫掠和制动预测定义；不同任务和预演不共享可写状态。

当前预置库不能只按名称复用

两份本机库均有 483 条组件记录，含 144 条 Test 项，自动泊车分类为 13 条。已发现 AStar、CollisionCheck 等同名条目使用标量演示模板；APA 包装虽有真实 C 调用，也仍需核对版本、场景上下文和状态行为。基础运算优先复用，复杂算法按实际实现分类评估。

单帧处理与异步边界

  1. 接收输入，核对身份、时序和新任务，优先处理保护反馈与输入故障。
  2. 更新任务与恢复决策；异步规划完成后，核对起点并用当前场景复核。
  3. 到达新控制步时：状态副本试算 → 可用距离检查 → 正式控制状态更新一次。
  4. 按本帧预测检查在线安全；必要时当帧停车、恢复或故障，不统一延后到下一帧。
  5. 完成指令覆盖 → C 执行器生成踏板 → 发布匹配帧输出；同帧重发复用缓存。

三项不能省略的实现契约

异步任务：请求身份、快照、取消、完成及过期结果拒收必须明确；没有假定某个官方任务组件已经存在。

状态隔离：在线控制、候选预演和搜索任务拥有各自状态；不得通过父子端口注入内部 State。控制与踏板执行器都只能按同一时间步推进一次；同帧新增安全事件可立即覆盖停车，但不能再推进滤波、偏置和积分。

场景与容量：100 点路径、64 条边界与 4096 个凸片不是同一数据层；不截断环境来迁就接口，不把请求级资源 ID 当作跨线程有效的地址。

Bridge 保持不动

地图与车位、占用判断、目标构造、CARLA 数据读取、命令与身份核验、转向适配和独立保护仍由当前 Bridge 承担。GAASD 保留原对外协议和 C 踏板所有权。
