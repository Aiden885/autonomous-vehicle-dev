## 1. 已确定的范围与读法

- 算法事实源：`apa_1112.zip`；Bridge 与外部交互事实源：`carla_bridge_1112.zip`。原 Simulink 只辅助解释，不据其补回当前两包没有的功能。
- `apa_1112.zip` 内的算法、任务组织、规划调度、控制与执行器功能全部纳入 GAASD。默认平台具备异步执行能力；不把原 `apa_planner_worker` 可执行文件作为必须保留的外部依赖。
- Bridge 暂不改变：地图与车位加载、实时占用、目标构造、CARLA 反馈获取、转向适配、命令核验和独立保护仍按现包执行；其 JSON/Protobuf 对应字段、版本与身份语义不得随内部命名改变。

- 本轮不修改源包、画布、组件数据库，不生成算法实现；异步任务绑定、数组表达和状态隔离还需在下一步用最小工程核对具体落地形式。

## 2. 为什么这样分层

推荐采用“业务子系统可展开、共性算法入库、复杂内核有边界”的方式，而不是两个极端：

- 全部拆成加减乘除：搜索、路径处理、碰撞检测会产生大量搬运数组的节点，职责反而不清楚。
- 整个规划或控制只包成一个不可展开大函数：无法解释候选如何产生、为何被拒绝、状态归谁，也无法复用其中的算法。

本方案采用三种表达：

- **画布子系统**：用于说明业务过程和组合已有能力，例如任务决策、候选生成、跟踪执行。不是每一个层级都要成为公共库组件。
- **复合算法组件**：承担可独立说明、测试和复用的完整计算，例如路径离散化、车辆扫掠检查、候选执行预演；内部按职责继续展开。
- **基础元件或受控算法内核**：基础算术、判断和限幅优先用现库；紧耦合搜索及事务式状态更新可保留有明确契约的内核，不能因此把整套 APA 隐藏起来。

“复合”描述组合职责，不直接决定扫描元数据中的 `block/atomic/element/component`。类型必须在选定生成规范后按实际结构登记，不凭中文分类猜测。

## 3. 工程与顶层画布

### 3.1 工程边界

```text
Bridge（本轮不改）
    ↕ 当前 ZMQ/JSON 协议
GAASD APA 工程
├─ 输入通信节点：沿用 ApaZmqInputModule 的协议行为
├─ APA 算法应用
│  └─ Main
│     ├─ ValidateInput       输入与时序校验
│     ├─ Decision            任务与恢复决策
│     ├─ Planning            异步路径规划
│     ├─ Control             安全运动执行
│     └─ PublishOutput       输出与诊断组织
└─ 输出通信节点：沿用 ApaZmqOutputModule 的协议行为
    ↕ 当前 ZMQ/JSON 协议
Bridge → CARLA
```

通信节点和后台调度也属于 GAASD 工程部署，不要求把 JSON 解析、进程管理等操作拆成算术方块。输入、输出节点名称在这里表示职责，不是已存在的通道组件登记名。

### 3.2 顶层每块解决什么问题

**ValidateInput**：这份反馈能不能使用，属于哪个任务和时刻？不得把无效输入补零后继续控制。

**Decision**：任务是否变化、何时规划、何时等待、是否接纳新路径，以及遇到问题如何处理？它管理任务，不计算几何路线或油门。

**Planning**：在冻结的起点和场景中找出可以采用的路线。它异步运行，不阻塞周期反馈处理，也不自行接管车辆。

**Control**：把已接纳的路径变成当前帧可执行的动作，内部包含执行状态、参考计算、运动安全约束及踏板执行。

**PublishOutput**：将最终指令、任务状态、规划版本、输入有效性及安全诊断按原契约对外发布。同帧重发不能重新积分或推进控制状态。

### 3.3 为什么不再额外摆一个总 Safety 方框

安全是完整的共性能力，但检查发生在不同位置：任务开始前、搜索扩展中、候选发布前、在线跟踪中和最终指令输出前。若把所有安全放成一个同步串行方框，容易出现“控制等安全、安全又等控制”的错误依赖。

因此顶层采用三个业务主体，分别在需要的阶段调用共享安全组件。共用的是算法定义和代码，不是让多个异步任务共享一个可写的安全状态实例。后续可以制作安全职责总览图，但不能把职责总览误当作实际调用顺序。

│  └─ EvaluateRecoveryProgress      检查重复恢复进展

### 4.1 生命周期不是简单清零

源码：`src/ApaModule.cc` 的 `Proc`、`ResetMocoState`、`LatchInputFault`。

输入为会话、任务、动作、启用状态、输入校验及 Bridge 保护反馈；输出为任务事件、允许状态及故障。任务身份真正变化时初始化；同一身份下已锁存的输入错误和故障不能靠切换启用位偷偷清除。原包已有的保持规则必须逐项映射。

该部分以状态比较、条件分支、状态读写和必要的复合模块实现，不直接将整个 `ApaModule` 封装成公共组件。

### 4.2 停稳与恢复

源码：`BeginRecovery`、`UpdatePlanning`，`module_lib/apa_recovery_context.*`，`XXX/src/ApaRecoveryDecision.cpp`、`ApaRecoveryObservation.cpp`。

`MatchStandstillConfirmation` 同时核对恢复编号、`stopped`、持续时间及当前速度，不只比较速度一次。Bridge 仍负责实际制动和反馈观察，不新增第二套 Bridge 停稳状态。

`AssessRecoveryContext` 处理风险类型、阻挡物变化、问题是否改变和跨次恢复是否取得进展。`SelectRecoveryAction` 保留 Hold、Observe、WaitForScene、Plan、PollPlanner、Fail 的实际优先关系。不能简化为“只要受阻就重算”，也不能无条件增加尝试次数。

恢复等待预算、单次规划看门狗和搜索计算预算是不同概念。当前 `attempt_timeout_sec=0` 表示关闭可选墙钟看门狗，不能将 `recovery_timeout_sec` 改解释为规划总耗时上限。墙钟与仿真时间也不能互换。

### 4.3 异步规划任务管理

源码：`StartPlanning`、`PollPlanningResult`、`module_lib/apa_planning_job.*`。

原来的 `posix_spawn/socketpair/Poll/Cancel` 是实现机制，不作为新画布中的业务算法逐条复制。改为 GAASD 内部的异步任务语义：提交、运行、完成、取消、失败，以及任务级不可变快照。

任务上下文至少关联会话、任务、恢复编号、尝试号和提交场景版本。取消后即使旧计算稍后返回，也不能激活它。异步任务释放、隔离和取消响应是平台绑定必须实现的契约，不在本文虚构具体官方 API。

### 4.4 结果接纳与路径状态

源码：`PollPlanningResult`、`CheckApaCandidatePath`。

worker/异步规划的成功只表示候选求解成功。接收端仍核对实际起点偏差并使用当前场景复核。通过后才更新路径、路径版本及控制重置事件。

当前源码起点偏差门为位置 0.1 m、航向 0.05 rad；这里只记录来源，不借重构修改阈值。场景版本发生变化不是一律拒绝的理由，应保留“用当前场景重新检查”的实际行为。

接受的完整路径由路径管理职责维护。控制仅得到业务路径与更新事件，不由父模块注入控制器内部 State。是否让路径管理在 Decision 内独立入库，取决于后续复用需求，不为一个赋值单独套子系统。

│  │  ├─ PlanVerticalTailIn         垂直尾入
│  │  ├─ PlanParallelParking        平行泊入
│  │  ├─ PlanDiagonalParking        斜列泊入
│  │  └─ PlanVerticalHeadIn         垂直头入
│  ├─ SearchParkingRoute            结构化搜索与连接
│  │  ├─ InitializeSearchRoots      初始化搜索根

│  ├─ CheckPathStructure            检查点列与方向

│  ├─ PreviewCandidateExecution     预演控制与车辆响应
│  └─ ImproveAcceptedCandidate      受控后处理

│  ├─ CheckRecoveryPermission       检查恢复许可
│  ├─ GenerateRecoveryPrefix        生成恢复前缀
│  └─ JoinAndRecheckRecoveryPath     连接并复核完整路线

这是职责导航，不是要求所有候选先全部生成、最后统一检查。搜索过程中已经调用碰撞和候选检查，检查结果也会影响下一批候选；不能按上树改成丢失反馈的纯串行算法。

### 5.1 请求解析不能越界接管 Bridge

源码：`ApaParkingRouteSelection`、`ApaParkingSlotPathPlanning`，`apaParkingSlotPathPlanning.c`、`apaParkingSlotTargetResolve.c`、`apaTargetSlotConstraint.c`。

本层检查和解释收到的目标、车位角点、入口边和车身约束，保留原生适配已有的归一化行为；不新增选车位、占用判定、地图查询或从视觉检测车位。

Bridge 已把车辆参考点转换到后轴中心，不能在 GAASD 再平移一次。原生接口保留其他调用方式时，其可选转换须按当前调用配置禁用或取零，而非删除接口含义。

### 5.2 四类几何规划

源码：`apaVtParkingPathPlanning.c`、`apaHtParkingPathPlanning.c`、`apaDthEdVtParkingPathPlanning.c`、`apaVhParkingPathPlanning.c` 及各自 `geo*` 依赖。

这四个业务规划器值得作为可展开的复合组件。内部共用坐标变换、直线/圆弧连接、入口和危险点计算、段检查及路径离散化，而不是在四个目录复制同一份几何实现。

`geoCircle2lineR`、双圆连接、圆弧与直线区间检查等具有稳定几何含义，可成为更底层公共组件。单次符号转换、一个条件或一个中间乘法不必各造一个专用 APA 组件。

### 5.3 搜索不是一个普通的每周期累加器

源码：`module_lib/apa_parking_search.cpp`、`apa_parking_motion.h`，`apaParkingSearchFallback.c`、`apaHybridAStar*.h`、`apaSearchTypes.h`。

Open/Closed、哈希、搜索节点、候选池和计算预算属于一次规划任务内部，不是车辆跨帧控制状态。搜索上下文由该异步任务独占；取消或任务结束后不能被下个请求继承。

搜索扩展、车辆运动连接和候选评估必须在设计中可解释。优先把车辆运动扩展、RS 连接、碰撞、路径恢复作为独立能力；优先队列、哈希和紧耦合工作内存不拆成满屏端口。搜索内核若保持受控原子粒度，必须有输入、输出、预算、取消与失败契约，不能仅用 atomic 标签规避依赖重构。

泊入允许从目标区域向实际车辆搜索，结果需变换为实际车辆到目标的执行顺序；泊出从实际库内位姿向库外目标搜索。不能简单反转点数组、不能给倒车车身航向额外加 π。

### 5.4 候选、离散化和后处理

源码：`apaParkingPathPlanning.c`、`apaParkingSearchFallback.c`、`apaParkingPathSafetyGate.c`、`apaParkingPathPostProcess.c`、`geoPthDiscret*`、`geoLnDirectDisctet.c`、`geoTrnDirectDisctet.c`。

候选保留点数、方向段、路径长度、业务元数据及有符号区间里程。质量比较先考虑实际换向次数，再结合短同向段和几何/近障等代价；不能改成只选最短距离。

后处理只有在质量改善，且重新通过曲率、完整扫掠和控制执行检查时，才能替换原候选；不是删除短段或任意平滑路径点。

原审阅记录中的首段离散点/里程不一致是现包的已知问题。架构保留一致性检查，后续单独修复和记录，不通过放宽安全门掩盖，也不把错误当作应保留的数学定义。

### 5.5 执行预演与受限恢复

源码：`apa_planning_job.cpp` 的 `ExecutionContext`、`PlanRegularPath`、`PlanClearanceRecovery`，`apa_tracking_execution.cpp` 的 `CheckApaTrackingExecution`。

`PreviewCandidateExecution` 需要独立的跟踪、执行器及名义车辆状态，复用在线控制算法定义，但绝不读取或修改在线控制实例的内部 State。每个候选应有明确初始化和结束条件，不能带着上一候选积分继续预演。

预演不是 CARLA 物理闭环；名义模型、方向/挡位、制动和安全检查都要保留。不能用较简化的 `apaParkingPathExecutability` 入口不加分析地替换当前 worker 的完整预演流程。

净距不足时的恢复前缀不是“允许碰撞”。它依赖当前源码的许可和冻结起点，长度、速度、时长及净距变化受限；需将前缀与后续路线作为完整候选检查，不能前缀先执行、后续稍后再算。虚拟约束与实体接触也不得混为一类。

### 6.1 执行状态与路径参考

源码：`apaMocoCtrlChartV2.c`、`apaMocoPathGeometry.*`、`apaMocoPathPointTransferV2.c`、`apaCtrlRefHandoff.c`。

方向段执行按 INITIAL、GEAR_CHECK、TRACK、DECEL、CREEP、STOP_WAIT、DONE、FAULT 等实际阶段组织。挡位确认、转向准备、停稳等待、无进展和超时不能只做成目标速度正负号。

路径投影限制在当前方向段及允许的历史进度窗口，不做整条路径的无约束最近点搜索。参考生成处理位置、航向、曲率及转向响应预看，不将离散点索引直接当作车辆真实进度。

状态归属：执行阶段与段号属于执行管理，已接纳投影进度属于跟踪实例；主任务决策只接收业务进度和完成/故障，不直接写这些内部状态。

### 6.2 横纵向计算与踏板执行应分开

源码：`apaMocoParkingControl.c`、`apaMocoLongiCtrlV2.c`、`apaMocoLatCtrlV2.c`、`apaMocoSteerCtrl.c`、`apaMocoActuator.c`。

`BuildSpeedEnvelope` 结合当前方向段、曲率、短段、剩余距离和近障约束构造速度限制。

纵向模块管理速度误差积分、加速度请求、饱和与 jerk 限制；加速度反馈项是否生效取决于实际参数，不能仅因代码有该字段就宣称默认启用。

横向模块组合曲率前馈、横偏、航向修正、受限空间积分和转向限制；积分更新与限幅关系按当前实现保留，不用通用 PID 替代。

`ActuateVehicle` 单独成为有完整物理意义的组件：读取速度、加速度、坡度项、目标与挡位反馈，生成最终踏板、手刹和挡位。它保留执行器滤波、偏置补偿、起步保持、变化率、超速和停车覆盖；输出所有者仍为 `C:apaMocoActuate:v2`，含原 `launch_hold` 语义。Bridge 不增加第二套闭环。

### 6.3 试算与正式更新不能画错

源码：`apa_tracking_execution.cpp` 的 `StepApaTrackingInScene`。

当前实现先在状态副本上计算候选控制，基于候选预测可用运动距离，然后以约束结果正式更新一次在线控制状态。若把两个调用画成同一个有状态组件连续执行两遍，会错误地积两次分、加两次计时并推进两次状态机。

因此上树表示计算职责，不表示现在就可以将原 C State 结构逐个作为子模块端口传递。落实时必须选定一个合法的状态所有权和试算提交边界：不得父组件复制、覆写或回传子组件内部 State；不得靠参数伪装成业务输入绕过隔离规范。

还要将同帧幂等性覆盖到踏板执行器。当前源码的缓存重放条件可因规划或安全事件改变而被绕过，后续仍调用有状态的 `apaMocoActuate`，静态上存在同帧重复推进滤波、偏置或变化率的风险，尚未动态复现。目标架构不得照搬这一风险：同帧新事件可以立即改变停车仲裁，但不能再次用正 `CycleTime` 推进执行器动态状态。安全覆盖与时间步推进必须分开。

如果规范要求与当前事务实现冲突，应明确记录并重划状态所有权或计算职责，再验证等价行为；不能以“封成 atomic”当作已经解决。这里只确定必须保持的计算顺序，不提前声称全部叶子已经可直接生成。

### 6.4 指令仲裁和结束

源码：`ApaModule::Proc` 控制、安全覆盖和 `apaMocoActuate` 调用前后的分支。

候选控制不是最终输出。当前帧的保护停车、输入故障、恢复停车、仅规划和超速等条件仍需覆盖运动请求。各分支沿原程序顺序和优先关系映射，不重新发明一张未经核对的优先表。

最终到位需要位置、航向、终点安全和持续停稳条件。`planOk/success` 是路径意义，`complete` 是控制意义，物理泊车效果还需记录验证。DONE 不等于关闭服务或自动发起下一次任务。

## 7. 共用算法库：什么值得新建

公共组件定义可以多处实例化，但每个实例的状态应独立。下面是职责候选，不是已发布的组件登记名称。

### 7.0 当前预置库的实际核查结果

已只读检查 `/home/aiden/.gaasd/gaasd.db` 和隔离版 `/home/aiden/gaasd_versions/gaasd-2.7.0.5/home/.gaasd/gaasd.db`。两者均有 483 条 component、12832 条 component_detail，含 144 个 Test 开头条目；不是 483 个已验证生产算法。两库名称集合一致，但多数数据库行 ID 不同，核对和复用应依 originId，而不是复制另一份库的行 ID。

按 component.tags 首级统计：基础模块库 96、功能模块库 145、基础支撑库 49、基础算法库 2、规划与控制库 87、自动泊车库 13、融合与决策库 24、感知与定位库 45，其他 22。此为数据库标签计数，包含测试和不同形态，不强行与界面筛选后的显示数量相等。

**可以优先复用的能力**：当前 Input/Add/TruthTable/ReadLocalState/Oscilloscope 等模板为 1.2.5，历史知识库的 1.2.0 不是当前事实；加减乘、比较逻辑、参数/状态读写等可继续使用。

**有真实计算但需核对契约的候选**：Clamp 对反置上下限报无效，但不能代替完整非有限数检查；AngleRegulate 使用循环归一化，必须先排除无穷输入。RateLimiter 有 initialized/previousValue 状态，首次直接通过且接受零采样时间，与 APA 变化率和初始化约定不一定相同。PidController 可参考结构，不直接替换 APA 的特定横纵控制律。

**不能按名称采用的条目**：当前 AStar 实现是标量求和、阈值比较、计数及数据透传，不是路径搜索。CollisionCheck/CollisionChecker、GenerateBezierPath、GenerateSpeedList、GetNearestIndex 也发现类似模板实现。因此不能把现库名称等同于完整算法，尤其不能用它们替换 1112 包的搜索、碰撞、路径恢复。

**13 个自动泊车条目**已经提供路径规划、业务路由、分车位规划和安全门等适配外形，部分确实调用原生 C 函数。可作为接口和组件形态参考，但含指针场景上下文、固定复制和局部状态处理；尚未证明与 1112 包同版、满足当前生成规范或有异步生命周期。应列为“改造复核”，不是直接宣称现成可用。

详情依据是 component_detail.extensionProps 内的端口、base_config.param/state 和 other_config.function_body，而非名称、分类或 isCustom 字段。

### 7.1 优先考虑的几何与路径组件

- **TransformVehiclePose，车辆坐标变换**：`apaCoordUtils.h` 及几何调用；输入位姿/点与参考坐标，输出变换结果；通常无状态。先查现库坐标轴、角度和旋转方向是否一致。
- **ConnectLineArc / ConnectTwoArcs，直圆与双圆连接**：`geoCircle2lineR.c`、`geo2CircleLink*.c`；完整切向连接问题值得入库，内部求交、角度与有效性可展开。
- **DiscretizeParkingPath，离散泊车路径**：`geoPthDiscretCommon.c` 及直线/圆弧离散器；统一输出位置、航向、有符号区间里程与点数。
- **CheckPathStructure，检查路径结构**：`apaPathInterval.h` 和候选结构检查；检查容量、有限值、方向、坐标/里程关系，不只检查点数。
- **ProjectPathProgress，路径进度投影**：`apaMocoPathGeometry.*`；适用于在线跟踪、预演及其他路径控制，但窗口与进度状态不能丢失。
- **CompareCandidateQuality，候选质量比较**：候选去重、换向与代价规则；APA 专属权重留在业务参数，不把通用排序与具体评价含义混为一体。

### 7.2 优先考虑的碰撞与安全组件

- **BuildVehicleEnvelope，构造车辆包络**：车身角点和八边形辅助实现；后轴参考点、前后悬、倒角与余量须明确。
- **CheckConvexCollision，凸形碰撞检查**：`collisionCheckSat.c`、`vehicleCollisionCheck*.h/.c`；可复用 SAT 类算法，但仅点碰撞不能替代整车。
- **CheckVehicleSweep，车辆扫掠检查**：`apaPlanningScene.h`、路径安全及运动预测；车辆包络沿线段/圆弧/预测运动的连续空间检查。
- **CheckTargetConstraints，目标约束检查**：`apaTargetSlotConstraint.*`、轮挡和第三边界相关实现；保留入口与非入口边、实体与虚拟约束的区别。
- **PredictStoppingMotion，响应与制动预测**：`apaMocoBraking.h`、`apa_motion_prediction.*`；反应、制动建立、转向响应和实际运动残差共同参与，不只使用理想匀减速距离。

### 7.3 优先考虑的控制与业务组件

- **ObserveStandstill，连续停稳观察**：GAASD 侧核对 Bridge 已有停稳反馈，不复制 Bridge 观察器；通用“持续条件确认”可用预置能力，任务编号匹配由业务层完成。
- **DecideRecoveryAction，恢复动作决策**：已有 `ApaRecoveryDecision` / `ApaRecoveryObservation`，优先整改后复用而不是从头画一大张真值表。
- **ManageManeuverExecution，机动段执行管理**：完整的停稳、挡位和阶段语义，适合有状态复合组件。
- **ComputeLongitudinalRequest / ComputeLateralRequest，横纵向请求计算**：复用现有算法定义和可解释的子计算，不用同名通用控制器直接替代。
- **ActuateVehicle，车辆执行器**：与控制律分离，既在线调用又用于独立名义预演实例。
- **StepNominalVehicle，名义车辆单步**：`vehicleDynamicStep.c` 与 `StepExecutionMotion`；预演还包含踏板、阻力和转向响应，不直接把通用运动学积分器等同于完整名义车辆模型。
- **PreviewCandidateExecution，候选执行预演**：复合组织独立控制实例、名义车辆、安全和终止判据；适合入 APA 业务库，不是现场实际控制。

### 7.4 不宜制造专用组件的情况

- 只有一个加法、限幅、比较、使能选择，且现库语义完全一致时，直接复用。
- 只为隐藏一个已有组件再套一层，不新增职责、参数或边界时，不建空壳子系统。
- 输入输出只是整包内部状态、指针、资源句柄或进程对象，而没有稳定业务语义时，先重划职责，不能直接登记为算法组件。
- 搜索、控制、预演之间重复出现的公共实现只保留一份定义；不同生命周期使用不同实例，不能复制源代码冒充复用。

## 8. 数据、参数和状态怎么组织

### 8.1 业务数据组

建议以车辆反馈、固定任务几何、当帧场景、规划请求/结果、已接纳路径、跟踪进度、运动请求、安全结果、踏板及诊断等业务组组织内部接口。组名不是外部协议重命名许可。

例如外部 `vehicle_speed`、`target_accel_mps2`、`path_point_odo` 等字段保持不变；内部组件字段可采用物理含义清楚的命名，并在边界显式映射。外部 JSON 的 `FrontWheelAngle`、`TargetAcceleration`、`StopReq` 等兼容字段也不能随意改写。

不把几十个字段在每层重复拉成满屏细线，也不让所有组件收发整个 ApaInput/ApaOutput。每个组件只拿完成本职责所需的数据，父子边界两层名称和类型一致。

显示命名参考现有项目：顶层使用 Decision/Planning/Control 便于辨认职责；新库组件英文名用大驼峰动词短语，中文名称/别名说明功能，内部业务端口用小驼峰。外部通道字段继续按原协议的下划线或兼容别名，不随内部命名规范改变。

### 8.2 容量与复杂数据

当前契约包含 100 点路径、各最多 64 条边界/虚拟线/轮挡线、各最多 128 个离散边界/轮挡点、最多 4096 个凸障碍片、每片 3～8 点以及 2 MiB 消息限制。它们属于不同数据层，不能用 64 条边界代替全部场景。

具体 Traits 表达须服从当前规范：固定数组、结构、维度展开及数值端口逐项核对。不直接让 Protobuf、`std::vector`、回调指针或进程内地址穿过画布模块边界；也不能为迁就端口擅自截断场景或减少搜索容量。

当前 `sceneQueryId` 是请求级资源注册方式，不是可携带到任意异步线程的普通整数。应优先把场景查询算法与任务内快照放在同一所有权域，或者使用平台明确支持的隔离资源机制。不能用“传一个 ID”掩盖共享可写场景和回调依赖。

### 8.3 参数与状态所有者

- 车型尺寸、转向尺度和规划余量继续以共享车型 JSON 为源，通过生成与校验保持一致；不在四个几何规划器里分别手填一套。
- 控制增益、周期、限速、容差、预算等明确为参数。上层调参不意味着父模块可以运行期写入子模块 Param；如何在 GAASD 界面方便配置，需按平台参数机制实现。
- 同任务请求容差只允许收紧等已有规则应作为明确业务约束保留，不能为符合规范而偷偷移除。
- 任务、恢复与版本状态由任务管理职责持有；搜索工作内存由异步规划实例持有；跟踪状态由在线控制实例持有；执行器滤波与偏置由执行器持有；预演拥有另外的实例。
- 重置、取消和新路径是业务事件，不是传递一包待写入子模块的内部状态。禁止全局单例同时存放在线和预演状态。

## 9. 调度和反馈：画布不能只按从左到右解释

同一帧应按原实现保留以下逻辑阶段：

1. 接收/合并输入，检查身份、时序和新任务，优先处理 Bridge 保护反馈与输入故障。
2. 更新任务及恢复判断，接收规划完成事件，核对并接纳结果。
3. 没有新控制步时复用缓存；有新步且允许执行时，进行试算、可用距离评估和一次正式跟踪状态更新。
4. 按本帧控制和预测检查在线安全；需要恢复或失败时，当帧改变任务响应并覆盖运动请求，不能一律等下一帧。
5. 应用恢复停车、故障、仅规划等覆盖，再生成最终踏板，发布匹配的身份、时间、路径与诊断。

上述顺序是语义要求，不是声称平台已有某个“异步任务块”。Decision 可以在同帧响应不同业务事件；“只更新一次”特指同一个控制时间步不能重复推进积分、执行计时、正式控制状态及踏板执行器动态状态，并非禁止任务状态响应同帧的新安全事件。原代码中的状态参数传递、线程局部场景资源以及同帧执行器风险需要明确重构，而不是默认已经满足目标约束。

规划运行在 GAASD 内的异步执行域；周期侧不等待搜索函数同步返回。冻结的是提交给求解的任务快照，在线安全仍使用当前帧环境，不能把冻结场景拿来长期代替在线环境。

## 10. 与 ACC/LKS 已有构建方式的对应

### 10.1 继承“物理职责为父、公式计算为子”

当前 ACC 数据库可见 `ACCControl → CalculateSpacingFeedback → multiply/fmax/subtract/multiply`。生成代码里父组件通过 Sub 保存子实例，建立 Input/Output 并调用子模块 run；基础元件在子模块内形成表达式。

APA 同样应让 `DiscretizeParkingPath`、`ProjectPathProgress` 等呈现完整物理职责，只在有利于解释和生成的位置下钻基础元件。不会因为 ACC 用乘法块较多，就要求搜索节点、哈希表和完整扫掠也画成基础块。

### 10.2 不照搬旧项目的状态集中写回方式

ACC 的历史生成流程读取当前状态、计算更新量再集中写回；它能说明“当前值”和“下一值”的区别，但不能直接授权父组件持有 APA 子控制器的 Param/State。APA 使用的 v3.8 对子模块隔离有更明确约束，必须按当前规范重划状态归属。

### 10.3 数据库与生成代码需要分开认定

当前 LKS 数据库为 `LKSControl → CalculatePreviewErrors → Near/Middle/FarPreviewError`；单点内部用乘加实现 Horner 多项式。同类历史生成代码展示了三个子实例的调用关系，但函数导出与当前数据库 UUID 大多不再对应，不能据此声称已有“最新代码等价证据”。

ACC 当前画布最终输出语义已为加速度，现存生成代码外层仍有旧 targetSpeedMps 名称。这里只借鉴构建形态，不把这些历史接口和生成结果当作 APA 的技术规范或已验证运行基线。

## 11. 实施前必须明确的设计检查项

- 异步默认成立，但仍需绑定具体提交/取消/完成事件机制，并验证旧任务结果不能激活新任务；不保留对外部 worker 可执行文件的必需依赖。
- 核对数组/业务结构、容量和生成器支持形式；不能先画出无法表达的数据接口再补丁生成代码。
- 核对试算提交、候选预演和独立实例重置，保证在线控制不被预演污染；控制与踏板执行器都必须同帧幂等，新增安全事件立即覆盖停车但不重复推进动态状态。
- 核对当前生成规范与原源码的参数/状态交互，显式列出需要职责重构的点，不导出子 State 绕过隔离。
- 参考当前 ACC/LKS 的实际画布和生成代码，而不是只用历史结构说明；组件库版本、元数据和属性配置必须重新读当前库。
- 外部输入输出、车型指纹、执行器所有权、同帧通信及失败状态保持可兼容；“全部进入 GAASD”不等于可以改 Bridge。
- 不把编译成功当作算法等价或泊车成功。后续依次比较输入契约、离散化、候选拒绝、控制单步、踏板、异步事件，最后再看物理闭环。

本版用于审核功能分层和职责归属。审核通过后，再制作逐组件端口、参数、状态、执行事件及现库/新增/改造清单；不直接开始批量创建画布。

独立约束复查另外确认：v3.8 对子 Param/State 的隔离要求优先于旧示例中的运行期 `setParam()` 写法；场景查询注册为线程局部且随作用域销毁。前者需要职责重构，后者要求异步执行域按本次快照创建并持有查询上下文，两者都不能用端口重命名规避。
