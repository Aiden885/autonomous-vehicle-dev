# 周报生成工具

这个工具用于把每周整理好的 Markdown 内容生成 `.docx` 周报，版式参考 `docs/templates/weekly_report_template.docx` 和历史周报。

## 固定约定

- 周报通常在每周一编写，内容由“上周已完成工作”和“本周工作安排”组成。
- 文档标题使用“规控小组”，文件名使用 `规控小组-X月第X周项目进展周报.docx`。
- 所有包含“负责人”列的表格统一填写 `赵煜坤`，不要填写“规控小组”。
- 文件头的 `owner` 是负责人唯一来源；生成器会用它统一覆盖进展、计划和协调事项中手工填写的负责人。
- 第一部分固定为“`一、上周核心工作`”，将原始日报合并为 1～3 个主题，通常保留 5～8 条核心工作。
- 第二部分固定为“`二、风险与问题`”；用户未提供风险时设置 `risk_header_only: true`，仅保留表头。
- 第三部分固定为“`三、本周工作安排`”，根据用户提供的安排和当前项目状态细化为可执行事项，但不虚构已经完成的结果。
- 技术名词、工程名、接口字段和测试结论应先与 `WORKLOG.md` 及当前项目文件核对。

## 1. 安装依赖

```bash
python3 -m pip install -r tools/report_generator/requirements.txt
```

## 2. 编写输入文件

每周一复制模板，并按实际周次修改文件名：

```bash
cp docs/weekly_inputs/template.md docs/weekly_inputs/2026-09-week1.md
```

填写以下几类内容：

- `## 进展：xxx`：上周已完成工作，每个进展模块会生成一张三列表格。
- `## 风险与问题`：当前风险、影响和应对措施。
- `## 下周工作计划`：下周计划项。
- `## 需要协调与帮助`：可选，没有可删除。

通常使用“本周工作安排”：

```yaml
plan_title: 三、本周工作安排
```

如明确编写下一周计划，可改为“`三、下周工作计划`”。

如需保留“风险与问题”的表头但不填写内容，可在文件头加入：

```yaml
risk_header_only: true
```

## 3. 生成周报

```bash
python3 tools/report_generator/generate_weekly_report.py \
  docs/weekly_inputs/2026-09-week1.md \
  -o docs/规控小组-9月第1周项目进展周报.docx
```

如果不传 `-o`，会默认输出到 `docs/{title}.docx`。

## 4. 输入格式

进展项支持两种写法。推荐省略负责人列，由文件头的 `owner: 赵煜坤` 自动补齐：

```markdown
- 任务项 | 完成情况
- 任务项 | 赵煜坤 | 完成情况
```

风险项：

```markdown
- 问题/风险 | 影响 | 应对措施
```

下周计划：

```markdown
- 计划项 | 计划内容
- 计划项 | 赵煜坤 | 计划内容
```

## 5. 建议流程

每周一由用户提供上周每日总结和本周安排。生成前先阅读最近三份周报、`WORKLOG.md` 和相关计划文档，再完成以下处理：

1. 合并同类项和重复日报，按“算法/画布、仿真/部署、接口/文档、方案研究”等主题归类。
2. 将口语化记录改写为“工作动作 + 对象 + 结果/作用”，不夸大、不写无法确认的结论。
3. 将本周安排细化为可执行步骤，保持与当前工程状态一致。
4. 检查所有负责人单元格均为“赵煜坤”。
5. 生成 DOCX 后检查标题、日期、章节、表格列数、负责人和压缩包完整性；环境允许时再渲染页面做视觉检查。

生成版式沿用历史周报的 A4 页面、微软雅黑字体、标题层级和三列表格宽度比例。
